# 插件与主体的实际边界

0.4.0 补齐 Git 插件所需的 SDK 基线。此前只分离了页面，仓库列表业务仍需要扩展宿主，这个边界已纠正。

| 层 | 负责内容 | 发布方式 |
| --- | --- | --- |
| Git 插件 `app.js` / `github.js` / CSS | 页面、账户选择、API 资源与分页参数、响应映射、搜索与筛选、克隆流程组合 | 独立 `.wbplugin` |
| 主体 SDK | 调用方身份与权限、目录授权、受限 Git 子命令、绑定账号的只读 GitHub 请求、凭据保管、浏览器打开 | 新增底层能力或权限时升级主体 |

GitHub 仓库列表由插件发起 `git.github.request(accountId, 'user/repos?...')`，宿主固定 GET、固定 API 域名并检查资源范围。插件不能传入令牌、HTTP 方法或任意 shell。克隆通过 `git.repos.cloneToFolder(accountId, remote, folder)` 请求原生选择器和 Git 操作，宿主验证目录与认证归属。

列表、分页、排序、布局以及上述资源范围内的新只读业务无需新宿主接口。新的写入操作、认证服务或原生 Git 能力仍需单独审查和扩展 SDK，不承诺任意功能永远无需升级主体。

验证覆盖插件脚本替换查询参数后仍调用相同宿主能力；真实账号列表及私有仓库克隆已验证。原生窗口及安装升级验证情况见更新记录。
