# MC 汉化 1.0.0

把已有汉化工具链接到工作台里：读整合包状态、改接口配置、起停流水线、看模组缺口和逐条译文。翻译本身仍由工具链的 `tools/pipeline.mjs` 执行，插件不重写一份实现。

工具链目录需要事先存在，默认找 `F:\Deepseek\mc-hanhua`（也读环境变量 `MC_HANHUA_ROOT`），目录里必须有 `tools/pipeline.mjs`。插件安装包只有约 100 KiB，不含工具链、游戏文件和任何译文。

## 安装与使用

主体保持 0.5.7，不需要重装。在「插件 → 在线获取」安装，或从本地安装 `mc-hanhua-1.0.0.wbplugin`。首次打开先确认两件事：侧栏底部显示「工具链就绪」，顶栏显示整合包名。

1. **概览**：填版本文件夹路径或点「选择文件夹」。选到 `.minecraft` 或 `versions` 上层目录时自动定位到唯一的版本文件夹；有多个候选会要求你自己选，不猜。可写探测失败会提示打包安装会失败。四张卡分别是模组键覆盖率、模组缺口、文本完成度、校验覆盖率，下面列出已装资源包、任务书中文文件数、缓存条数和缺口合计。
2. **翻译**：先跑「只估算」看规模，不调接口、不花钱；确认后再「AI 翻译」。可以限定范围（全部 / 只要模组 / 只要任务书 KubeJS）、命名空间和本次最多翻多少条。「只打包回写」不发请求，把已有译文打包安装。日志面板实时显示流水线输出，进度条按步骤和批次推进，「停止」用 `taskkill /T` 结束整棵进程树。
3. **接口**：Base URL、模型、API Key、并发和每批条数。Key 只写工具链目录的 `config.local.json`，页面不回显，只显示尾四位；「清除已保存的 Key」写入后从文件里删除。「测试接口」发一个小请求验证连通与返回格式。
4. **模组清单**：按缺口或覆盖率排序，只看有缺口的；点行或「缺口最多」的标签打开预览，逐条对比英文与中文，中文右侧标记来源（`AI` 是插件/流水线译的，`自带` 是模组 jar 里已有的）。「翻译这个模组」把命名空间填进翻译页，不自动开始。

## 数据与文件

- 插件自己的设置存在宿主数据目录的 `settings.json`：工具链目录、整合包路径、可选 node 路径。运行日志另存 `pipeline.log`，每次运行前截断。
- 整合包路径同时写回工具链 `config.local.json` 的 `packPath`，让命令行入口和插件用同一个包；只改这一个字段，文件里其它字段原样保留。
- 统计全部来自工具链的既有产物：`work/modstats.json`、`work/gap.json`、`work/verify.json`、`work/packver.json`、`work/tm.jsonl`、`work/zh-mods/<包名>.json`、`work/jars/assets/*.json`、`dist/*.zip` 和 `resourcepacks/` 里已装的包。插件不写这些文件。
- 预览最多 300 条，按语言文件顺序。

## 权限与边界

- 权限只有 `folders.read` 和 `native.backend`：前者用于选目录和取宿主授权的路径，后者运行本机后台。不申请网络、浏览器或代理权限。
- 页面通过宿主的 CSP 运行，`connect-src 'none'`，所以没有轮询之外的长连接，也没有任何外部请求；状态 3 秒、日志 1.5 秒各拉一次，窗口隐藏时暂停。
- 后台跑在宿主的本机后台进程里，`process.execPath` 是 `electron.exe`，所以起流水线前会自己找 node（`MC_HANHUA_NODE` → PATH → Program Files → LocalAppData），找不到才用 `ELECTRON_RUN_AS_NODE`。
- 一次只跑一个任务；已有任务在跑时再点开始会被拒绝，先停止。
- 不内置模型凭据，也不替用户申请模型服务。接口地址和 Key 都由使用者自己填，费用与内容由使用者自己的账号承担。
- 这是本机可信插件的做法：后台有完整本机代码权限，不是操作系统级沙箱。
