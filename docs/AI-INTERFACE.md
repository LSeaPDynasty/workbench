# 外部 AI 数据访问 v0.1

## 范围

不运行模型，不管理模型密钥，不创建聊天界面。外部支持 MCP 的客户端通过桥接进程访问正在运行的应用。第一版仅支持读取，不提供任意 SQL、脚本执行或文件系统浏览。

## 调用链

MCP 客户端 → stdio 桥接进程 → Windows 命名管道 → 宿主权限检查 → 插件查询 → 数据服务。

命名管道限制为当前用户访问，并采用显式配对凭据；凭据不放在命令行参数和日志中。相同用户权限的恶意程序不在完整隔离保证范围内。MCP 客户端身份不能只根据自报名称信任。

## 首版能力

| 工具 | 参数 | 返回 |
| --- | --- | --- |
| workbench_list_apps | 无 | 已启用且已授权应用及查询能力 |
| workbench_search | appId、query、limit、cursor | 摘要、稳定 ID、下一页游标 |
| workbench_get_record | appId、collection、recordId | 授权记录详情 |

每次调用重新校验授权与插件启用状态；插件声明 aiReadable 只是具备暴露资格，不等于用户授权。默认关闭外部访问，在设置中逐应用开启。查询默认 20 条、最多 100 条，响应大小上限和超时在原型阶段确定并测试。

接口只返回业务记录，不返回凭据、内部路径或未授权附件。资源文本按不可信内容处理，不能将文档中的指令提升为系统操作授权。记录审计事件：客户端配对 ID、插件、查询名称、时间、结果和耗时，不保存正文。

应用未启动时返回 APP_NOT_RUNNING，桥接进程不自行直接读取数据库。撤销配对立即阻止后续调用。未来写接口需独立权限、幂等设计和操作确认机制，不能沿用只读授权。
